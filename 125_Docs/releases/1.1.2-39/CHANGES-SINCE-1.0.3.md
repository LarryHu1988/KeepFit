# KeepFit：1.0.3（32）至1.1.2（39）更新汇总

核对日期：2026-10-26，Asia/Shanghai。以下区分最新App中实际生效的更新、中间测试版已开发但当前主入口未开放的能力，以及配套数据维护工程。

| 对比项 | 1.0.3（32） | 1.1.2（39） |
| --- | --- | --- |
| 分发状态 | App Store已分发，READY_FOR_DISTRIBUTION / READY_FOR_SALE | TestFlight Pilot内部测试，VALID / IN_BETA_TESTING |
| 代码依据 | Git提交99d8dc9 | 本次发行源码SHA-256清单；当前文件与上传时清单一致 |
| 食物目录 | 174项内置食物 | 13,535条营养齐全的来源记录 |
| 日常记餐方式 | 时间、食物选择、数量、添加 | 保留同类选择框，增强搜索和图谱驱动的单位、营养计算 |
| 食物搜索 | 已有名称搜索 | 搜索框常显，增加别名匹配、营养信息与无结果状态 |
| 数据更新方式 | 内置代码维护 | 图谱主库及整理层导出离线数据包，随App版本更新 |

1. **食物成分图谱与搜索**

- 接入13,535条四项营养完整、允许用于App的来源记录，保留稳定食物ID，不按同名强行合并。
- 支持中文名、英文名和别名搜索；搜索框在食物选择页常显。
- 选择项从仅显示热量，扩展为显示基准量、基准单位、热量、蛋白质、脂肪、碳水和营养依据标签。
- 增加“其他食物”分类；保留来源原分类不明的事实。
- 匹配结果较多时显示前200项并提示继续搜索，避免一次性渲染上万行；增加无匹配结果提示。
- 未授权来源不进入App；53条核心营养不完整的授权来源记录暂不进入可选目录，不将缺失值填成0。
- 食物名称、英文名、图标、分类、别名、计量基准和营养值可在数据层维护，不需逐条改Swift界面。

实际范围：当前包只有76条记录具备整理后的中文显示名，其余主要保留英文原名；不是13,535种全部完成中文整理的独立食材。许多条目的图标和分类仍使用来源分类的通用表示，后续可逐项完善。

2. **单位、数量和营养计算**

- 数量框的单位、默认数量改为读取所选食物的基准，不再仅按食物ID或饮品分类决定。
- 四项营养按“输入数量÷基准数量”统一缩放。
- 数据接口支持g、mL、个、碗、份等单位和小数数量。
- 只有提供明确的每单位克重时才做质量换算；没有密度或克重依据时，不把mL、个或碗当作g。
- 默认数量不再取整或只保留一位小数；保存时拒绝非有限数、零和负数。

实际范围：当前13,535条正式条目全部来自每100g数据，因此实际选择后使用g。mL、个等计算已通过临时测试条目验证，正式图谱尚需补充这些单位的数据。

3. **历史记录与数据兼容**

- 在原有每100g营养快照基础上，补充记录当时的输入数量、单位、四项营养汇总和来源快照。
- 进食列表及“减个肥”的日记录使用已保存的份量描述、单位和图标。
- 后续图谱调整基准或营养值，不重新计算已经保存的记录。
- 新数据包按完整目录替换，已从图谱删除的条目不会因旧目录缓存再次出现。
- 旧版记录缺少新增字段时仍可解码，沿用原有营养计算。

4. **热量、体重和体脂趋势图**

- 三种趋势图改用实际绘图区宽度与实际日期文字宽度安排横轴标签。
- 修复日期标签出现中间漏一项、间距失衡、布局变化后残留旧日期的问题。
- 空间足够时展示全部日期，空间不足时均匀抽取，尽量保留区间两端。
- 日期字号、纵轴字号、边缘留白与图表高度随可用宽度及系统字体尺寸调整。
- 图例在横排空间不足时切换竖排，减少文字挤压。
- 时间范围按钮根据实际栏宽采用紧凑布局，改善窄屏或双栏中的显示。

5. **DUO适配、页面布局和系统视觉**

- 三个主页统一使用自适应页面容器；窄屏保持单列纵向滚动，采用按需布局。
- 包含DUO专门适配：在iOS 27.1及以上、设备提供中间分隔区域且满足展开横屏宽度条件时，切换为双栏；概览与记录/图表各自滚动，避开设备中间预留区域，并由原生TabView处理侧边导航及安全区域。收起或不满足双栏条件时使用单列。
- 卡片、周历、进度环和趋势区根据所在栏宽布局，减少依赖整屏宽度造成的尺寸偏差。
- iOS 26及以上使用原生Liquid Glass标签栏；旧系统保留原有材质方案。
- 隐藏滚动条，统一页面观感。

2026-10-27补核：DUO布局所在的MainTabView及三个主页、趋势图文件均与1.1.2（39）上传时源码校验清单一致；归档版本也是1.1.2（39），确认已包含在该发行包中。

边界：双栏逻辑有系统、屏宽、横屏和设备分隔区域条件，不能表述为所有iPad或所有横屏设备均已全面支持；本轮发布不等于真实折叠设备姿态验收。

6. **添加、保存与切页反馈**

- 进食添加、锻炼添加、体重体脂保存统一使用带反馈的操作按钮。
- 保存成功时短暂显示勾选，并有图标切换/弹动反馈。
- 旧系统按钮增加按压缩放、渐变和光晕；iOS 26使用原生可交互玻璃效果。
- 切换三个主页时增加轻量、依次出现的卡片过渡；入场与部分按压动画参考“减少动态效果”设置。
- 补充添加进食、添加锻炼、保存体重体脂等无障碍操作标签。

7. **设置、分享、评分和其他作品**

- 改进分享状态传递，修复首次点击系统分享页的问题；分享卡片在本地提供KeepFit名称和图标预览，减少对网络预览的依赖。
- 评分入口进一步简化为固定官方App Store评分链接；打开失败时显示提示。
- 分享、反馈、关于等设置行扩大可点击区域。
- “关于”更名为“关于KeepFit”，开发支持显示“Larry Hu”；反馈联系方式仍保留在反馈功能中。
- 新增“更多APP”，展示简值·SimpleWorth和PDF Librarian，包含各自图标、用途、平台要求、App Store入口及产品主页。

注意：正式App Store链接分享、评分入口以及Apple登录后的设置/数据同步修复，1.0.3发布说明中已经包含；这里列的是其后的进一步改进，不应把这些基础能力重复宣传为首次新增。

8. **隐私说明和账号清理**

- App内及仓库隐私政策补充云端饮食识别的数据处理说明，包括本餐文字/图片的发送范围、图片缩放和元数据移除、语音转写、云端草稿及记录保留方式。
- 增加相机、麦克风、语音识别用途说明，并扩展照片权限用途文案。
- 删除账号流程增加先验证身份并清理云端识别数据的逻辑，再执行原有本地/iCloud记录清理与同步关闭；相关真机流程仍需验收。

这些更新是为曾加入的云端识别模块提供配套；不代表最新“管住嘴”主界面仍开放文字、语音和拍照按钮。

10. **配套后台和验证工程**

- 建立独立食物营养主库与本地图谱浏览器，保留来源、版本、原始营养、缺失/异常标记和官方份量；提供查询与CSV/SQLite导出。
- 建立App离线JSON合同、人工整理层、稳定ID、版本化导出和原子替换流程。图谱更新后重新导出并随App新版本分发，当前没有远程实时更新。
- 新增图谱导出及单位换算、旧记录兼容、营养快照、实际App资源加载、搜索选择保存的回归验证。
- 新增趋势日期轴的多组合检查及设置分享/关于/更多App的界面检查。
- 已完成1.1.2（39）的Release归档、发行签名、包内容核验、上传、Apple处理及Pilot分发；中英文测试说明回读一致。

可核实的本轮结果为34项数据库测试、7项Swift合同测试和1项完整记餐UI流程通过，以及发行包签名及内容验证通过。后台完整采集库、机器译名缓存、工作台、截图与测试工具不等于全部进入用户手机，也不计作额外的iOS界面功能。
