# KeepFit 饮食识别如何使用

这套服务已经接进 KeepFit 源码。你和其他 App 用户都不需要理解 API 或填写模型密钥。

在新版本的「管住嘴」点「打字」「语音」或「拍照」，第一次使用 Apple 登录。描述实际吃下的东西，例如「午饭半碗米饭、三块红烧肉，四个人吃菜，我没喝汤」。语音会先变成可修改文字；照片可以补充自己吃了哪些、剩了多少。

点击识别后，核对菜品和份量。如果信息不够，选择补问答案或直接打字回答；理解不对时直接纠正。接受明确标注的估算，再点确认，记录和营养会进入这餐日期的统计。

数据来源支持的基础食物会显示来源，常见菜会显示配方与用油假设；其它食物保留模型估算说明。半碗、三块可以作为原始份量显示，不要求你先准确称重。

「记一餐」右上角可删除云端识别数据；手机已保存的记录保留。删除 App 账号时，会先验证账号并删除对应云端识别数据，再删除手机和 iCloud 的该账号资料。

## 当前可用状态

服务器和专用 HTTPS 已上线，MiMo 按量密钥已由所有者安全配置并验证。真实早餐识别、多人共餐补问、接受估算和确认记录的服务流程通过，共执行3次真实调用；这些测试使用合成餐食，未修改你的进食记录。以后 App 用户无需填写密钥。

App 接入代码和合成界面流程测试通过，仍需用真实设备验收 Apple 登录、录音、食物照片和完整保存流程。

目前试用限制为全服务每天最多10次模型调用，用户每人每天最多10次；回答补问和纠正也需要调用。已发出的失败请求同样计数，没有自动重试。以后扩大测试时再调整额度。

1.1.1（38）已上传 TestFlight，Apple 处理通过，并进入 Pilot 内部测试。请在 TestFlight 更新到这一版，再从「管住嘴」使用三个入口；真机验收仍需完成。

## 以后给其它 App 使用

这套服务使用统一的饮食草稿、补问、纠正、确认与营养结果接口。其它开发者可接入同一套服务，但公开给第三方前还需完成开发者账号、按调用方配额/计费、授权与稳定性验证。当前接口不代表已经开放注册的商业 API，也没有进行模型权重微调。
