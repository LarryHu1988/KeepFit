# KeepFit 饮食识别服务

线上服务已部署，已接通 MiMo 按量 API；2026-10-24 的3次真实进食理解与补问调用通过。App 接入源码和合成界面测试通过；1.1.1（38）已上传 TestFlight 并进入 Pilot 内部测试，真实设备验收仍待完成。日常 App 使用说明见[试用与接入说明](试用与接入说明.md)。

本地工作台可用于可视化调整规则和纠正案例，与线上 App 使用隔离的记录和连接。以下为本地工作台操作方法。

**[打开工作台](http://127.0.0.1:8765/)** · 服务版本 0.3.0 · 2026-10-24

## 只需这样使用

1. 点击右上角 **模型设置**，选择 DeepSeek 或 MiMo，填写该平台的 API 密钥，然后点击 **验证并连接**。这里只查询模型列表，不进行付费推理。密钥不要发到聊天中。
2. 在 **试用模型** 输入一顿真实饮食，例如“中午半碗米饭、三块红烧肉，四个人一起吃菜，我没喝汤”，点击 **开始识别**。
3. 右侧查看菜品、本人实际份量、营养估算和估算依据。若有问题，在左侧直接选择选项或用自己的话回答。
4. 理解不对时，在 **哪里理解不对** 写下纠正，点击 **按我的纠正重新理解**。可同时把这次纠正保存为以后参考的案例。
5. 在 **调整规则** 中设置追问习惯、是否允许常见份量估算和自己的补充要求。保存后从下一次请求开始生效。
6. 满意后勾选接受估算，点击 **确认这条记录**。工作台确认保存到工作台历史；App 内的新流程会在确认后将整餐导入当天统计。两种客户端各自使用隔离的账户与记录。

下次服务未启动时，在 Finder 中双击本目录的 **打开 KeepFit 工作台.command**，它会打开页面；不要关闭启动服务的终端窗口。服务关闭后需重新填写平台密钥。

## 这次交付的能力

- **真实模型适配**：DeepSeek Flash 和 MiMo Flash。模型平台密钥由你自己的账户提供。
- **可视化试用**：输入、结果、补问、自由纠正、确认、历史记录。
- **可视化调教**：自定义规则、追问风格、是否允许估算；最近 6 条启用的纠正案例参与后续请求。
- **拍照**：上传 JPEG / PNG 食物照片，并补充自己吃下的量。上传前在浏览器缩小长边至不超过 1600 像素，转换为 JPEG。
- **语音**：浏览器支持时使用网页转写，支持情况取决于浏览器和麦克风权限；部分浏览器会使用自己的在线识别服务。不支持时可在输入框使用 Mac 系统听写。转写文字可修改后再提交。
- **小额试用控制**：每次服务启动默认最多 10 次模型请求，用完后需在界面明确开启下一轮。每次最多输出 4096 tokens，没有后台自动测试或自动重试。次数包含失败的已发出请求；金额以平台账单为准。

## 关于“培训好的模型”

目前是 **基础模型 + KeepFit 专门的饮食理解规则 + 你的纠正案例 + 营养计算与确认流程**。规则和案例会真实提供给基础模型，帮助它理解半碗、剩余、改口、成品菜和共餐等场景。

这属于规则和示例调教，**还没有进行模型权重微调，也没有宣称达到某个识别准确率**。后续需要积累有授权且经过核对的案例，用独立测试集验证，才适合讨论参数训练。

营养处理接入 USDA 官方 CC0 数据的22种基础食物，保留 FDC ID、数据版本与来源；仅匹配明确对应的名称和做法。另有8种明确说明配方、用油与成品重量的常见菜估算。未覆盖的食物保留模型估算或待补问，不强行匹配生熟不同的食物，不当作零热量。此覆盖范围尚不能代表完整中餐库或经过准确率验证。

## App 的三种入口

“管住嘴”提供打字、语音、拍照。语音先由 iOS 转成可编辑文字；照片在发送前缩小并重新编码以移除拍摄元数据。结果可补问、纠正，接受估算后确认整餐写入当前 App 的进食记录，原话、份量、营养来源一并保留。重试使用固定记录ID防止重复入账，旧记录按原数据读取。

## 数据与密钥

本地工作台的密钥仅存于本机服务内存；不写入 SQLite、不返回页面、不记录日志。线上服务的密钥由所有者安全保存到服务器私有文件，App 用户无需填写。页面在本机自动建立会话，不需要你手动复制服务 token。

描述、规则、纠正案例和记录保存在本目录 `.data`，默认不上传整份历史。每次识别发送本次描述或照片、当前规则、最近 6 条启用案例；后续补问还发送当前这餐的结构化观察。图片不写入记录数据库。规则和案例一经参与请求，就会发送给选定模型平台。

本地工作台默认只监听 `127.0.0.1`。线上模式采用独立服务器、Apple 登录和服务器持久化调用上限，不公开工作台。部署状态与限制见 [部署说明](deploy/README.md)。开发者 API 保留 Bearer 认证、调用方隔离、幂等和草稿版本检查。浏览器会话采用 HttpOnly / SameSite cookie，并验证写入请求来源。
